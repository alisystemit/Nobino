# 🪞 نوبینو (Nobino)

سیستم **نوبت‌دهی صوتی آرایشگاه** بر پایه هوش مصنوعی که به هر آرایشگاه یک صفحه و ساب‌دامین مجزا می‌دهد.

مشتری با میکروفون به زبان فارسی نوبت می‌گیرد؛ سیستم گفتار را به متن تبدیل می‌کند (Whisper)، نوبت را در دیتابیس ثبت می‌کند و در زمان مقرر **پیامک یادآوری** می‌فرستد. هر آرایشگاه / نماینده / سوپرادمین **پنل مالی دقیق** دارد و پکیج‌ها از طریق **۱۵+ درگاه پرداخت ایرانی** فروخته می‌شوند. کل سیستم قابل افزودن به وب‌اپ **تلگرام / ایتا / بله** است.

---

> 📘 **مستندات کامل کاربری و فنی:** فایل [`DOCS.md`](./DOCS.md) را ببینید.

## 🧱 تکنولوژی

| لایه | انتخاب |
|---|---|
| فرانت + بک‌اند | Next.js 16 (App Router) + TypeScript |
| استایل | Tailwind CSS v4 |
| دیتابیس / ORM | PostgreSQL + Prisma 6 |
| هوش صوتی | OpenAI Whisper (با درایور Mock برای توسعه) |
| احراز هویت | شماره موبایل + OTP (JWT) |
| پیامک | ۱۰ سرویس‌دهنده ایرانی (انتخابی پویا از پنل ادمین) |
| پرداخت | ۱۵+ درگاه (Adapter + Sandbox) |
| استقرار | Vercel + Neon (Postgres) یا VPS اوبونتو با یک فرمان از GitHub |

## 🚀 اجرای محلی

### ۱. پیش‌نیازها
- Node.js 18+
- PostgreSQL (لوکال، یا رایگان از Neon/Supabase)

### ۲. نصب
```bash
npm install
```

### ۳. تنظیمات
```bash
copy .env.example .env
# سپس مقادیر DATABASE_URL و ... را وارد کنید
```

### ۴. دیتابیس

**گزینه الف — یک‌فرمانی (پیشنهاد برای شروع سریع):** یک PostgreSQL قابل‌حمل و محلی بالا می‌آورد، دیتابیس می‌سازد و seed می‌کند (نیازی به نصب PostgreSQL ندارد):
```bash
npm run db:local
```

**گزینه ب — اتصال به PostgreSQL موجود (لوکال یا Neon/Supabase):**
```bash
npm run db:generate   # ساخت Prisma Client
npm run db:push       # اعمال schema (یا npm run db:migrate)
npm run seed          # داده‌های نمونه (۱ سالن، ۳ پکیج، کاربران تست)
```

### ۵. اجرا
```bash
npm run dev
```
باز کنید: `http://localhost:3000/s/mah`

**کاربران تست seed:**
| نقش | شماره |
|---|---|
| سوپرادمین | `09120000000` |
| آرایشگر | `09120000001` |
| نماینده | `09120000002` |

**سالن نمونه:** `http://localhost:3000/s/mah`

**ورود سوپرادمین (بدون پیامک):** `http://localhost:3000/admin/login` با `admin@nobino.ir` و رمزی که در `.env` با `ADMIN_PASSWORD` تعیین کرده‌اید (پیش‌فرض `Admin@1234`). اگر رمز را گم کردید روی سرور: `node scripts/reset-admin-password.mjs`.

### قالب نمونه کامل (۶ سالن با عکس و گالری)

```bash
npm run db:demo            # ساخت ۶ سالن نمونه + کارکنان + گالری + نوبت‌ها
npm run db:demo -- --assets-only   # فقط بازتولید فایل‌های تصویری در public/seed
```

تصاویر بنر/لوگو/گالری به‌صورت برداری در پوشه `public/seed/` داخل ریپو commit شده‌اند؛ پس روی سرور تازه‌کلون‌شده هم بی‌درست موجودند و نیازی به آپلود ندارند. فایل‌های آپلودی واقعی کاربران در `public/uploads/` می‌مانند و هرگز با اجرای مجدد قالب نمونه بازنویسی نمی‌شوند.

## 🧪 حالت توسعه بدون سرویس‌های خارجی

با پیش‌فرض‌های `.env` همه‌چیز در حالت «شبیه‌سازی» کار می‌کند:

- **SMS** = در حالت پیش‌فرض سرویس فعال «کاوه‌نگار» است، اما چون کلیدی تنظیم نشده به‌صورت خودکار **شبیه‌سازی (mock)** استفاده می‌شود و کد OTP/پیامک‌ها در کنسول سرور لاگ می‌شوند.
  > سوپرادمین می‌تواند از «پنل ادمین ← تنظیمات سیستم» بدون تغییر کد، سرویس پیامک را عوض کند و کلیدهای ۱۰ سرویس‌دهنده ایرانی (کاوه‌نگار، اس ام اس.آی‌آر، فراز، قاصدک، ملی پیامک، ایران اس ام اس، پیام رسان، ناکالای، موبایل اس ام اس، آرپانو) را وارد کند.
- **Voice** = `mock` → به‌جای Whisper یک جمله نمونه فارسی برمی‌گردد (بدون کلید API).
- **نمایش کد ارسالی در صفحه ورود** = در حالت توسعه کد OTP/ایمیل بلافاصله زیر فرم ورود نشان داده می‌شود. در پروداکشن این نمایش **خاموش** است و تنها با روشن‌کردن سوئیچ «نمایش کدهای ارسالی در صفحه ورود» در «پنل ادمین ← پیامک» (کلید `sms.show_sent_codes`) فعال می‌شود.
  > ⚠️ این سوئیچ فقط برای تست است؛ روی سرویس پیامک واقعی حتماً خاموشش کنید، چون هر کسی با دانستن شماره می‌تواند کد ورود را ببیند.
- **PAYMENT_DEFAULT_GATEWAY** = `sandbox` → پرداخت در حالت تست شبیه‌سازی می‌شود.
- **درگاه‌ها** = همه `sandbox=true` → بدون مرچنت‌کد ه‌را در گزینه «پکیج» می‌توانید تست کنید.

برای فعال‌سازی سرویس واقعی، کافی است مقادیر مربوطه را در `.env` بگذارید
(مثلاً `VOICE_PROVIDER="openai"` + `OPENAI_API_KEY=...`).

## 🖥 نصب خودکار روی VPS اوبونتو — فقط با لینک GitHub

روی سرور اوبونتو **یک فرمان** کافی است؛ کد از همین ریپوی عمومی دریافت می‌شود و
نیازی به آپلود دستی فایل‌ها نیست:

```bash
curl -fsSL https://raw.githubusercontent.com/alisystemit/Nobino/main/scripts/install-from-github.sh | sudo bash
```

### سرور خام یا سرور دارای Apache/Nginx؟

اسکریپت اول فقط سرور را بررسی می‌کند (بدون تغییر) و بعد مسیر خودش را انتخاب می‌کند:

- **سرور خام (هیچ وب‌سروری ندارد):** همهٔ پیش‌نیازهای لازم نصب می‌شود — Node.js،
  PostgreSQL، Nginx، PM2، بیلد پروژه و در صورت داشتن دامنه گواهی SSL و فایروال
  UFW. این پروژه به PHP یا MySQL نیاز ندارد و هیچ‌کدام نصب نمی‌شوند.
- **Apache یا Nginx از قبل نصب است:** همان وب‌سرور **استفاده** می‌شود و پروژه در
  `/var/www/nobino` کنار سایت‌های دیگر قرار می‌گیرد. فقط یک فایل اختصاصی اضافه
  می‌شود (`/etc/apache2/sites-available/nobino.conf` یا
  `/etc/nginx/sites-available/nobino.conf`) و وب‌سرور reload می‌شود. سایت‌ها،
  دامنه‌ها، پوشه‌ها و گواهی‌های SSL بقیهٔ برنامه‌ها **تغییر نمی‌کنند**.
- **دامنهٔ تکراری:** اگر دامنهٔ واردشده قبلاً برای سایت دیگری تنظیم شده باشد، به
  آن سایت دست نمی‌زنیم؛ Nobino روی اولین پورت آزاد **8080 تا 8099** منتشر می‌شود
  و همان دامنه با پورت قابل استفاده است.
- **آدرس عمومی:** دامنه و پورت نهایی پیش از هر نصبی تعیین می‌شوند و همان آدرس
  به‌صورت پیش‌فرض در `.env` (متغیرهای `NEXT_PUBLIC_APP_URL` و
  `NEXT_PUBLIC_SITE_URL`) نوشته می‌شود؛ در پایان نصب هم آدرس کامل چاپ می‌شود.
- **PHP و MySQL:** این پروژه فقط Node.js و PostgreSQL می‌خواهد. اگر PHP،
  MySQL/MariaDB یا LAMP برای برنامه‌های دیگر روی سرور باشد، نه نصب، نه ارتقا،
  نه ری‌استارت و نه بازتنظیم می‌شود.
- **دیتابیس:** اگر PostgreSQL موجود باشد استفاده می‌شود؛ در غیر این صورت نصب
  می‌شود. یوزر/رمز قبلی **هرگز تغییر نمی‌کند**: اگر role هم‌نام وجود داشته باشد
  ولی رمزش معلوم نباشد، یا دیتابیس هم‌نام متعلق به نقش دیگری باشد، یک role و
  دیتابیس جداگانه با پسوند ساخته می‌شود.
- اپ با یک **کاربر اختصاصی و کم‌دسترس** (`nobino`) اجرا می‌شود، نه root؛ خانهٔ
  کاربر `/var/lib/nobino` است و خود اپ فقط روی `127.0.0.1:3000` گوش می‌دهد.

> سؤال‌ها از ترمینال (`/dev/tty`) خوانده می‌شوند، پس اجرای pipe تعامل را از بین
> نمی‌برد. اگر کد از قبل روی سرور است: `sudo bash scripts/deploy-ubuntu.sh`.

**انتخاب‌های دلخواه با متغیر محیطی** (همه اختیاری):

| متغیر | پیش‌فرض | شرح |
|---|---|---|
| `REPO_URL` | `https://github.com/alisystemit/Nobino.git` | ریپوی منبع (برای ریپوی خصوصی با توکن هم کار می‌کند) |
| `GIT_REF` | `main` | برنچ، تگ یا کامیت برای استقرار |
| `APP_USER` | `nobino` | کاربر سرویس (بدون دسترسی root) |
| `APP_DIR` | `/var/www/nobino` | پوشه نصب، کنار سایت‌های وب‌سرور |
| `PORT` | `3000` | پورت داخلی Next (فقط روی 127.0.0.1) |
| `WEB_SERVER` | `auto` | `auto/apache/nginx` — auto یعنی وب‌سرور موجود استفاده شود و روی سرور خام Nginx نصب شود |
| `WEB_PORT` | `80` با دامنهٔ آزاد، وگرنه پورت آزاد 8080+ | پورت عمومی؛ مقدار صریح همیشه رعایت می‌شود (پورت 80 فقط با دامنهٔ آزاد) |
| `MANAGE_UFW` | `auto` | `auto/1/0` تنظیم فایروال (auto فقط روی سرور خام روشن است) |
| `ENABLE_SSL` | `auto` | `auto/1/0` گرفتن گواهی با certbot (auto وقتی دامنه و پورت 80 آزاد باشد) |
| `DOMAIN` | _(خالی)_ | دامنهٔ اختصاصی همین نصب؛ خالی = نصب فقط با IP و پورت |
| `SSL_EMAIL` | `admin@DOMAIN` | ایمیل تماس certbot |
| `APP_URL` / `ROOT_DOMAIN` | از `DOMAIN` | آدرس عمومی و دامنه ریشه ساب‌دامین‌ها |
| `NONINTERACTIVE` | `0` | با `1` هیچ سؤالی پرسیده نمی‌شود |

نصب بی‌سؤال (مثلاً روی سرور اختصاصی با دامنه `nobino.ir`):

```bash
curl -fsSL https://raw.githubusercontent.com/alisystemit/Nobino/main/scripts/install-from-github.sh \
  | sudo DOMAIN=nobino.ir SSL_EMAIL=admin@nobino.ir NONINTERACTIVE=1 bash
```

نصب روی سروری که Apache دارد و دامنهٔ جدا برای Nobino:

```bash
curl -fsSL https://raw.githubusercontent.com/alisystemit/Nobino/main/scripts/install-from-github.sh \
  | sudo DOMAIN=app.example.com NONINTERACTIVE=1 bash
```

اگر دامنهٔ جدید ندارید، `DOMAIN` را خالی بگذارید؛ اسکریپت یک پورت آزاد 8080–8099
انتخاب می‌کند و آدرس نهایی را در پایان چاپ می‌کند.

**به‌روزرسانی بعدی** — اسکریپت `update-ubuntu.sh` کد را از GitHub می‌گیرد، قبل از
هر کاری از `.env` و دیتابیس پشتیبان می‌سازد، وابستگی‌ها را نصب می‌کند، schema را
اعمال می‌کند، اپ را build و با PM2 ری‌استارت می‌کند و در پایان سلامت سرویس را
با یک درخواست محلی چک می‌کند:

```bash
curl -fsSL https://raw.githubusercontent.com/alisystemit/Nobino/main/scripts/update-ubuntu.sh \
  | sudo bash -s -- --dry-run      # پیش‌نمایش، بدون هیچ تغییری
curl -fsSL https://raw.githubusercontent.com/alisystemit/Nobino/main/scripts/update-ubuntu.sh \
  | sudo bash -s -- --yes
```

اگر فایل‌ها روی سرور هستند، از همان‌جا هم اجرا می‌شود:

```bash
sudo bash /var/www/nobino/scripts/update-ubuntu.sh
sudo bash /var/www/nobino/scripts/update-ubuntu.sh --ref v1.0.0 --stash
```

گزینه‌ها: `--dir` (مسیر نصب؛ پیش‌فرض خودکار `/var/www/nobino` و بعد `/opt/nobino`)،
`--ref` (برنچ/تگ/کامیت)، `--stash` (تغییرات دست‌ی را موقتاً کنار بگذار تا کد جلو
برود)، `--replace` (پوشه‌ای که `.git` ندارد را به چک‌اوت گیت تبدیل کن؛ پوشهٔ قبلی
حذف نمی‌شود، با پسوند `.old-تاریخ` کنار نگه داشته می‌شود)، `--skip-deps`،
`--no-build`، `--full` (بعد از آپدیت، `deploy-ubuntu.sh` را هم اجرا کند تا فایل
سایت/vhost بازسازی شود)، `--dry-run`، `--yes`.

این اسکریپت چیزی را در سیستم عوض نمی‌کند: وب‌سرور، SSL، فایروال، Node، PostgreSQL
و هیچ سایت دیگری نصب، حذف یا بازپیکربندی نمی‌شود و رمز یوزرهای PostgreSQL تغییر
نمی‌کند. برای نصب اولیه یا تغییر دامنه/پورت، `deploy-ubuntu.sh` را اجرا کنید:

```bash
sudo bash /var/www/nobino/scripts/deploy-ubuntu.sh
# یا یک تگ مشخص:
sudo GIT_REF=v1.0.0 bash /var/www/nobino/scripts/deploy-ubuntu.sh
```

اگر پوشهٔ نصب تغییرات دست‌ی (commit‌نشده) داشته باشد، اسکریپت آن را **پاک نمی‌کند**
و فقط هشدار می‌دهد. نصب‌های قدیمی‌تر که در `/opt/nobino` ساخته شده‌اند هم خودکار همان پوشه را ارتقا
می‌دهند (مگر اینکه `APP_DIR` را دستی مشخص کرده باشید).

**حذف کامل:** هر بخش (PM2، وب‌سرور، SSL، دیتابیس، فایروال، Node، پوشه، کاربر
سرویس) جداگانه پرسیده می‌شود و فقط چیزی که تأیید کنید حذف می‌شود؛ قبل از حذف
دیتابیس هم پشتیبان `pg_dump` گرفته می‌شود. فقط vhost/فایل اختصاصی Nobino حذف
می‌شود؛ سایت‌های دیگر، PHP و MySQL/MariaDB دست‌نخورده می‌مانند و بستهٔ Apache
هیچ‌وقت حذف نمی‌شود:

```bash
curl -fsSL https://raw.githubusercontent.com/alisystemit/Nobino/main/scripts/uninstall-ubuntu.sh \
  | sudo bash -s -- --dry-run      # پیش‌نمایش، بدون هیچ تغییری
sudo bash /var/www/nobino/scripts/uninstall-ubuntu.sh
```

پس از نصب، ادمین پیش‌فرض سید با شماره `09120000000` وارد شوید و رمز را عوض کنید
(`sudo -u nobino -H env HOME=/var/lib/nobino bash -lc 'cd /var/www/nobino && node scripts/reset-admin-password.mjs رمز-جدید'`).

## 🌐 استقرار روی Vercel

1. پروژه را به GitHub پوش کنید.
2. در Vercel پروژه جدید بسازید (framework: Next.js).
3. دیتابیس را روی [Neon](https://neon.tech) یا Supabase بسازید و `DATABASE_URL` را در Vercel قرار دهید.
4. در Vercel روی `Settings → Environment Variables` همه متغیرهای `.env.example` را مقداردهی کنید.
5. Build command: `npm run build` (معمولاً خودکار).
6. در Vercel Cron یک Job برای «ارسال پیامک یادآوری» بسازید (هر ساعت).

**ساب‌دامین سالن:** دامنه `nobino.ir` را به Vercel وصل کنید؛ `proxy.ts` به‌طور خودکار
`salon.nobino.ir` را به `/s/salon` هدایت می‌کند.

   ├─ prisma.ts
   ├─ env.ts

   ├─ sms/                     # provider.ts
   ├─ payments/                # gateways/* + engine + registry
   ├─ financial/               # wallet, commission

   ├─ seed/                    # تصویرهای برداری قالب نمونه

prisma/
   ├─ schema.prisma

```
